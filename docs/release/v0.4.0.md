MeshDrop 0.4.0: copy anything across, and a security pass.

**Shared clipboard: anything**
- Copy an image or files on one device and they arrive on the other's clipboard, ready to paste (text worked before). On the PC, files copied in the file manager; on the phone, images and files copied in other apps.

**Pairing codes**
- Pair and Add by address now show a 6-digit code. The other device shows the same code: pair only if they match. A different code means someone is in between, and nothing is trusted.

**Security fixes**
- Internet links: each file a visitor sends back is sealed with a key of its own; old visitor sessions are cleaned up.
- Hub: changes to the mesh (invites, joins) must be signed by the member; strangers that connect and stall, or flood before logging in, are dropped sooner; a limit per address.
- LocalSend: the other device's certificate is checked before anything is sent; devices with LocalSend's encryption turned off are refused.
- Folder sync never reads a file through a linked folder that points outside the synced folder.
- A received program or script (.sh, .desktop, .AppImage, .exe…) opens its folder instead of starting.
- Android: a file shared to MeshDrop by another app can no longer point at MeshDrop's own private files.
- Slow or silent connections are closed sooner on the PC and the phone.
- Guests page: says that guest links are not encrypted (use them on Wi-Fi you trust).

Existing pairings and meshes keep working. A second PC on 0.3.x can no longer make invites through a 0.4.0 hub PC: update it too.
